# 验证记录

日期：2026-10-11。对象：补丁 1.0.1，官方 NDM 1.3 / Build 24，Apple Silicon macOS。

## 构建及签名

- 从官方 NeatDMInstaller.dmg 中提取的完整应用构建，版本、主程序 SHA-256 和全部 18 个 NIB 指纹匹配。
- 18 个 NIB 共修改 378 处显示引用，原资源、动作和出口引用保持不变。
- 两种架构各修改 13 个命令 CFString 对象。独立 UTF-16 存储位于头部空闲区域，整个原 `__cstring` 段不变。
- 8 个原分类/状态常量不变；侧边栏代码仅转换最终显示，arm64 为 347 字节、x86_64 为 473 字节。
- 主应用及快捷键模块本地签名，完整 `codesign --verify --deep --strict` 通过。
- Safari 扩展逐文件与官方输入一致，保留官方开发者签名及原沙盒权限。
- 本机安装应用与通过界面测试的构建结果逐文件一致。安装保留被替换的完整应用备份。

## 自动测试

`python3 tests/run.py`：5 项结构/安装测试通过；arm64 与经 Rosetta 运行的 x86_64 分别通过侧边栏和 AppKit 快捷键测试，共 4 次原生执行。

侧边栏测试实际执行编译后的汇编，检查全部 8 项中文转换、非匹配字符串和 nil；快捷键测试检查修饰键、原关闭动作、sheet 取消与父窗口保留。

设置 `NDM_ORIGINAL_APP` 后，额外 2 项真实二进制回归检查通过：整个 ASCII 字符串段不变；全部 8 个内部分类/状态 CFString 对象不变。未提供原版时明确跳过这两项。

## 实际界面测试

- 官方原版与修复版对照使用同一条用户提供的长下载链接；修复版新建下载能够开始下载，取消能够关闭下载窗口。为避免下载大文件，测试立即暂停。
- Chrome 已安装扩展自动接管本地 3.1 MB ZIP，NDM 完成下载。
- Safari 扩展在设置中恢复，右键链接选择 “Download by NeatDownloadManager” 后，NDM 完成本地 ZIP 下载。
- 设置、关于能够正常打开；设置、关于和下载完成窗口的 Command-W 关闭有效。
- 侧边栏 8 项中文和对应原图标正常显示。

测试未关闭 Safari，也未中断 Safari 中已有下载。没有将用户下载链接、账号参数、任务数据库或诊断日志加入源码。

Safari 普通点击链接的自动接管并未作为本次通过项；仅确认官方扩展恢复及其右键送出下载功能。上述验证不代表所有网站、网络场景或其他 macOS 版本已完整测试。

## 1.0.2 一键安装验证

- 缺少 `original/NeatDownloadManager.app` 时，`./install.sh` 明确提示完整放置路径，并停止操作。
- 新增 3 项入口流程测试：缺少原版、应用仍在运行、构建失败，均在安装前停止。现有结构/安装测试和两个架构的原生测试继续通过。
- 使用官方安装卷中的原版，在含空格的隔离项目路径运行 `./install.sh --build-only`，完整构建及签名通过。
- 在隔离目标目录执行完整校验、构建、备份及安装流程；新应用与构建结果一致，备份与替换前应用一致。隔离测试仅跳过全局运行进程检查；真实入口及安装器保留两次检查。
- 本机 `/Applications/NeatDownloadManager.app` 在测试前后全部文件指纹一致，没有重新安装或退出用户应用。测试副本在验证后清理。

## 1.0.3 备份目录验证

- 成功安装后，旧应用和 JSON 记录均位于项目 `backup/`，目标应用所在目录没有备份 App。
- 模拟备份复制失败，原已安装应用保持不变，临时目录清理。
- 模拟安装后校验失败，原应用恢复，失败副本保存在项目 `backup/`。
- 用新目录中的 JSON 记录完成安装/恢复往返，恢复时也将被替换应用备份至项目 `backup/`。
- 测试仅操作隔离临时应用目录，没有替换用户当前安装的 NDM。
